## 0. 规范目的与使用方式

### 0的目的
让整个平台「看起来像同一套产品」：同一功能同一样式；颜色、字号、边距、圆角、交互有**可执行条款**；后续新页直接套模板，而不是再发明一套。

### 0.1 三层关系

| 层 | 文档 | 作用 |
|----|------|------|
| **目标规范（本文）** | `design_system_spec.md` | 品牌风格 + 对标结论 + 页面结构 + Token + 组件 **应当怎样** |
| **落地路线** | `design_system_rollout.md` | 典型页 → 系统页审计清单与逐页调整顺序 |
| **实现记忆** | 各 `*_mobile_*` / palette 记忆 | 改码细节；**与本文冲突时改实现或提例外，不静默偏离** |

### 0.2 工作流（已确认）

```
① 定目标规范（本文 v2）
    ↓
② 对照规范审计「典型页」并调整至达标
    ↓
③ 对照规范审计「每一个系统页」并逐一调整
    ↓
④ 直至每个页面元素均按规范实现（可回归抽检）
```

## 1. 品牌总体设计风格

### 1.1 品牌一句话

**BERNSINE·阿卡贝拉** = 可信的中文人声社区：温暖、有仪式感、信息清晰，像懂行的朋友在带路，而不是冷科技后台或娱乐短视频壳。

### 1.2 视觉关键词（必须同时成立）

| 关键词 | 含义 | 设计表现 |
|--------|------|----------|
| **酒红仪式感** | 品牌识别 | CTA、选中态、关键标题点缀用 `#6f0718`；禁止大面积实心酒红铺底 |
| **暖米氛围** | 温馨可停留 | 功能面/空态/弹层用暖米渐变；列表托底微暖，白卡浮起 |
| **暖金点缀** | 精致不艳 | 细描边、角标、把手条；禁止大块金色 |
| **信息流克制** | 像主流内容 App | 灰底白卡、京东式筛选芯片、少阴影少贴纸 |
| **认知优先** | 运营宗旨 | 标签/筛选/热度序贴合用户心智（见 `ops_cognition_principle`） |

### 1.3 气质正反例

| 要 | 不要 |
|----|------|
| 小红书/酷安式信息流密度 + 自有酒红暖米 | 紫蓝 AI 渐变、霓虹发光、玻璃拟态堆砌 |
| 京东式筛选芯片（冷灰底 + 品牌选中） | 每页自定义圆角芯片 |
| 微信读书/知乎式阅读字号层级 | 详情页标题忽大忽小 |
| B 站式沉浸短视频（独立深色） | 把 Shorts 强行套暖米底 |
| 主色只做强调 | 整屏酒红、高饱和彩虹标签 |

### 1.4 品牌色板（目标 Token · 强制）

| 角色 | Token | 色值 | 用法 |
|------|-------|------|------|
| 主色 | `--b2-brand` | `#6f0718` | 选中、链接强调、主按钮、底栏激活 |

对标对象选「中文移动内容/社区 + 桌面阅读」，不是抄皮肤，而是抄**结构纪律**。

| **小红书** | 双列封面卡、标题克制字重、沉浸感 | 其红主色、强运营贴纸 |
| **京东** | 筛选芯片：冷灰未选 + 品牌色选中描边、高 24、字 12 | 电商价签、复杂促销条 |

| **淘宝底栏** | 线框/填充双态图标逻辑 | 电商营销动效 |

## 2.1 桌面端策略（≥769px）· 响应移动改版但不盲搬

近几天移动端已大幅统一（暖色 Token、灰底白卡、京东式芯片、阅读字号、边距令牌等）。**桌面端必须跟进品牌与组件语义**，同时遵守桌面网站的操作习惯与信息架构——不是把 App 壳层放大到显示器上。

### 2.1.1 专业原则（三条）

| # | 原则 | 含义 |
|---|------|------|
| 1 | **Token 同源** | 品牌色、筛选选中语义、阅读层级、圆角阶梯与移动一致；禁止桌面另起一套酒红/灰 |
| 2 | **壳层异构** | 桌面用顶栏导航 + 宽内容区 + hover；**不**搬底栏五格、不搬 safe-area、不搬「工具条三键挤一行」 |
| 3 | **密度与指点重定向** | 鼠标精确指点 → 可更密、可靠 hover；触控大按钮逻辑不必原样搬；点击目标仍需可辨 |

### 2.1.2 必须对齐移动的（视觉身份）

| 项 | 桌面做法 |
|----|----------|
| 品牌色 / 暖米 / 暖金 | 同一 `--b2-*` |
| 列表托底 | 目标 `--b2-list-bg`（与移动收敛一致） |
| **列表卡语义（§7.7）** | meta 矩阵、空摘要不占位、封面热度叠层、同族封面比、**标题/摘要行数按场景**——与移动**同一套**；勿桌面缺赞评浏览、空摘要占高或标题只 1 行 |
| 筛选**选中语义** | 冷灰未选 + 浅酒红底 + 品牌描边/字（对齐 facet；淘汰「实心品牌+白字」第三语义） |
| 阅读层级关系 | H1 > 正文 > 元信息；桌面字号可略增（见下）但比例不变 |
| 主/次按钮 | 同组件语言 |
| 空状态 | 同暖米 + muted |

### 2.1.3 必须保持桌面习惯的（交互壳层）

| 项 | 桌面应保留 / 采用 | 禁止盲搬 |
|----|-------------------|----------|
| 主导航 | 顶栏菜单 + 快捷入口横排；可 hover 下拉 | 底部 Tab Bar |
| 筛选 | **面板展开**（`#filter-top` 多行维度）或轻量下拉；一级芯片可横排 | 默认「搜索\|排序\|筛选」三键抽屉为主路径 |
| 列表宽度 | 内容区限宽（约父主题 `--b2-width` / 1100–1200）居中；多列网格 | 左右只留 12px 的手机边距感 |
| 卡片 | 可用更宽多列；卡内字段与叠层同 §7.7 | 把手机双列**列数**硬套桌面；**封面比仍按同族矩阵**（内容流 3/4 等） |
| **目录库单卡信息区** | `.post-info` 左右 inset↑（约 16；文案勿撑满卡宽） | 双列 `.post-info` **`10px 12px 12px`**（左右/底勿再压成 6/5）；**勿用改列数凑卡宽** |
| 详情 | 正文集中栏 + 可选侧栏（作者/相关）；行长约 60–75 字 | 移动端通栏窄阅读的一切留白照搬 |
| 发布 | 居中卡片/宽编辑区；顶栏操作 | 底部 Sheet 圆角把手当唯一形态 |
| 短视频 | 桌面可用栅格列表 + 点击进播；沉浸可用更大播放器 | 竖屏全屏手势栈 |
| 指针态 | `:hover` / `:focus-visible` 明确 | 仅有 `:active` 触控态 |

### 2.1.4 桌面尺寸建议（目标档，可在落地时微调）

| 档 | 移动 | 桌面建议 | 说明 |
|----|------|----------|------|
| 列表 gutter | 12 | 内容区随 wrapper；卡间距 12–16 | 不是把 12 当视口边距 |
| 列表标题 | 14 | 14–15 | 勿突然 18+ 破坏克制 |
| 阅读 H1 | 20 | 22–24 | 略升，层级仍压过正文 |
| 阅读正文 | 15 | 16 | 行高仍 ≥1.7 |
| Facet/芯片高 | 24 | 28–32（面板内） | 可点面积略增；**选中色语义不变** |
| 圆角卡 | 10 | 10–12 | 勿桌面一律大圆角网红风 |

### 2.1.6 桌面对标（补充）

| 参考 | 取什么 |
|------|--------|
| 知乎 / 少数派桌面 | 限宽正文栏、顶栏导航、侧栏相关 |
| B 站桌面 | 顶栏 + 内容栅格；播放器页独立 |

### 2.1.7 落地顺序（桌面）

1. **先共享 Token/芯片选中语义/托底**（改一处两端受益）  
2. **再桌面壳层与面板**（`#filter-top`、分类桌面头、首页模块限宽）  
3. **最后逐模板扫桌面特判**（详情侧栏、发布页、赛事模块等）  
4. 凡移动-only 的 critical CSS，**禁止**在无 `@media` 保护时污染桌面

## 4. 页面模板（结构规范）

所有系统页必须声明自己属于哪一种；新增页不得「四不像」。

### 4.1 模板 L · 列表（标准信息流）

```
托底 --b2-list-bg
  左右 gutter 12
  ┌ 白卡 r=10 ─────────────┐
  │ 封面（类型角标 · 底缘热度）│
  │ 标题 14 / 400 · 最多 2 行（桌面=移动）│
  │ 摘要 12 / muted · 最多 1 行（桌面=移动·可缺省·不占位）│
  │ 作者·时间 10–11 / meta   │
  └────────────────────────┘
  卡距 10
```

- 对标：酷安 / 小红书信息流 + B 站封面叠层热度。  
- 适用：P01/P02/P04/P05/P07–P14/P16/P20 等。  
- **移动与桌面同一卡片语义**（字段、空摘要、封面热度、同族封面比）——见 §7.7；壳层差异（列数/顶栏）见 §2.1。  
- **列表样式**：B2 `post-1`=网格、`post-2`=瀑布流；首页推荐为瀑布流，多数分类内容流为网格。

### 7.7 列表卡片（认知优先 · 全端强制）

> 宗旨：显示哪些字段、封面比、空摘要是否占位——服从**贴合用户认知**；**移动与桌面同一语义**。  
> 实现：`functions-list-meta-cognition.php` · `functions-list-thumb-ratio.php` · `child.js`（`tidyEmptyPostCardMeta` / `relocatePostThumbMeta` / `syncHomeWaterfallLayout`）· `style.css` 全端规则。  
> 日更：`run.sh list_meta`（含 thumb 比例校准）；亦可 `run.sh list_thumb`。  
> 记忆：`list_meta_cognition` · `list_thumb_ratio` · `category_post_meta_ui` · `home_load_more_mobile`。

#### 7.7.1 Meta 显示矩阵（`post_meta`）

| 场景 | 保留 | 去掉 | 理由 |
|------|------|------|------|
| **内容流**（首页推荐 / 短视频 / 视频 / 精选 / 教程 / 赛事） | 作者 · 时间 · 摘要 · **封面**赞/评/浏览 | **分类名 cats** | 封面类型角标已表达类型；分类页再写「短视频」冗余 |
| **目录库**（乐团 / 音乐人 / 组织） | 摘要 · **封面**浏览 | 作者 · 时间 · 分类 · 赞评 | 标题即身份；WP 作者/时间是噪声 |
| **乐谱**（模板 L-row） | 浏览；改编/演唱等字段 | 作者 · 时间 · 分类 · 赞评 · 摘要行 | 领域字段优先 |
| **快捷入口** | 各页自有模型 | 禁止硬套文章卡全套 meta | 快讯=时间线；练习=声部/BPM；公告=日期+摘要；声场=作者+互动；导航=标题+描述 |

**封面热度叠层（哔哩哔哩式 · 移动+桌面）**

| 项 | 定稿 |
|----|------|
| 位置 | `.post-module-thumb > .b2-thumb-meta` 底缘 |
| 视觉 | 矮黑渐变（约 `max-height:36%`）+ 白字 11px；勿大黑条 |
| 顺序 | **浏览 → 评论 → 喜欢** |
| 原位 | `.post-list-meta-box` 加 `b2-meta-relocated` 后隐藏 |
| 空态 | 无 like/comment/views 节点时**不造**空渐变条 |
| 断点 | **全端**；禁止仅写在 `max-width:768` |

**实现约束**

1. 靠后台/矩阵**取消勾选**让 DOM 不输出；**禁止**用 CSS `display:none` 盖掉已勾选的 des / user / date。  
2. 赞/评/浏览必须进封面叠层（上表）；JS 挪位 + CSS 全端。  
3. 日更校准，防止后台又勾回全选或改乱封面比。

#### 7.7.2 空摘要要不要占位

| 列表样式 | B2 | 空摘要 | 定稿 |
|----------|-----|--------|------|
| 瀑布流 | `post-2`（如首页推荐、赛事） | **不占位** | 卡片本就高低不一 |
| 网格 | `post-1`（如多数分类） | **不占位** | 中间留白比「略矮」更难看；假占一行帮不上齐行 |

**定稿**：无论网格/瀑布、移动/桌面，**无摘要一律不占位**（`.b2-excerpt-empty` → `display:none`）。有摘要时最多 1 行。  
判定：文案 trim 后为空、仅 `&nbsp;` / 零宽字符、或仅为 `...` / `…`，均视为空。  
标记：`tidyEmptyPostCardMeta()`；因摘要常用 `-webkit-box !important`，须 class + CSS，勿指望普通 inline hide。

**反例**：为「网格齐高」预留一行透明摘要；或空摘要 CSS **只写在移动 media** 导致桌面标题下空一截。

可选增强（非必须）：网格卡 `.post-info` flex + `.list-footer { margin-top:auto }`，把高度差沉底。

#### 7.7.3 封面比例（同族统一 · 强制）

> 不全站一个比例：素材形态不同。同认知族统一框比，跨族用比例提示类型。  
> 字段：B2 `post_thumb_ratio`（宽/高）；目录库与 `post-3` 同步 `post_thumb_ratio_pc` / `_mobile` 同值。  
> 实现：`functions-list-thumb-ratio.php`；日更随 `list_meta`。

| 族 | 比例 | 分类 / 首页模块 |
|----|------|-----------------|
| **内容流**（双列网格 / 瀑布） | **3/4** | 短视频 · 精选 · 教程 · 入门教程 · 赛事；首页 `new` / `short` / `latestarticles` / `video` |
| **视频单列** | **16/9** | `video`（`post_row_count_mobile=1`；桌面可多列但仍用此横比） |
| **目录库** | **1/1** | 乐团 · 音乐人 · 组织 · hot_band；首页 `wangge` / `pubu` |
| **乐谱** | 不纳入 | 模板 L-row（`post-6`），勿跟网格比 |

**反例**：精选 `7/4`、教程 `4/3`、短视频 `9/12` 各设一套——同是内容双列却节奏散乱。

#### 7.7.4 瀑布流布局（Packery / 多列 · 强制）

首页推荐（`#home-row-new` · `post-2`）与赛事等瀑布流，在挪封面 meta、藏空摘要后卡片高度会变——必须重排，否则列内大块白洞。

| 端 | 策略 |
|----|------|
| **移动**（≤768） | CSS `column-count` 瀑布；`destroy` Packery，清 li 的 inline `top/left` |
| **桌面**（≥769） | 保留 Packery；高度变化后 `reloadItems` + `layout`（`relayoutHomeWaterfallPackery`） |
| **触发** | `tidyEmptyPostCardMeta` 之后、load-more、`b2PackeryLoad`、首屏延时、resize / load |

统一入口：`syncHomeWaterfallLayout()`。赛事分类页同类问题用其既有 `relayoutPackery`。

**反例**：只在移动端 neutralize Packery，桌面藏摘要后不 `layout` → 列间空洞。

#### 7.7.5 全端实现纪律（列表卡）

下列样式与行为属于**产品语义**，不是「移动增强」——**必须写在无断点限制的全局规则**（或同时覆盖桌面）：

1. `.b2-excerpt-empty` / `.b2-footer-empty` 隐藏  
2. `.b2-thumb-meta` 叠层与 `.b2-meta-relocated` 隐藏原 meta 行  
3. 封面比例由矩阵写入 option/term，不靠仅移动端 CSS 假装统一  
4. 标题/摘要行数（§7.7.6）全端 CSS `!important` + 后台 `post_title_row` 双端同值  

**坑（已踩）**：把上述规则只放进 `@media (max-width: 768px)` → 桌面空摘要占位、无赞评浏览叠层、瀑布流白洞、标题只 1 行。

#### 7.7.6 标题与摘要行数（桌面 = 移动 · 分类可配 · 场景默认）

两端行数必须一致。**场景矩阵只是默认种子**；同一认知族内各分类可在后台单独改（例：同是目录库，乐团 1/2、另一分类可 2/1）。

| 场景默认 | 名称 `.post-info h2` | 摘要 `.post-excerpt` | 说明 |
|----------|----------------------|----------------------|------|
| **内容流**（短视频/视频/精选/教程/赛事/首页推荐等） | **2** | **1** | 标题信息量优先；摘要点到为止 |
| **目录库**（乐团 / 音乐人 / 组织 / hot_band；首页 wangge/pubu） | **1** | **2** | 标题即身份；摘要给 2 行（可按分类改） |
| **乐谱**（L-row） | **2** | —（通常无摘要行） | 领域字段优先 |

> **字号/边距 ≠ 行数**：内容流列表项的标题/摘要**字号与 `.post-info` 上下左右边距**对齐乐团（桌面 `10/16/8`、移动双列 `10/12/12`；标题 14、摘要 12、摘要上距 4）。行数仍按上表场景默认。

**空摘要**：仍不占位（§7.7.2），与行数无关。  

**配置（分类 `b2_group`）**  
- 标题：父主题 `post_title_row` + `post_title_row_mobile`（保存时子主题同步为同值）  
- 摘要：子主题 `post_excerpt_row`（1–3；桌面=移动）  
- 前端：`wp_head` 输出 `--b2-list-title-clamp` / `--b2-list-excerpt-clamp`（覆盖场景 CSS 默认）  

**校准**：`b2child_list_title_rows_apply_all` **只补空 / 同步 PC=移动，不覆盖已配置**（随 `run.sh list_meta`）。

**反例**：日更把后台改过的行数又刷回场景默认；或桌面/移动标题行数不一致。

## 10. 实现约束（研发）

1. 新样式 **只允许** 使用本文 Token / 阶梯值。  
2. 改移动芯片或边距时，`style.css` 与 `functions.php` critical **同步**。  
3. 禁止新增第三种芯片视觉。  
4. 禁止新增第三种列表托底色。  
5. PR / 调整说明须标注：页面 ID（Pxx）+ 模板（L/R/F/S/M/T）。  
6. **列表卡语义（§7.7）全端落地**：空摘要、封面热度叠层、同族封面比、瀑布流重排、**标题/摘要行数按 §7.7.6 分场景**——禁止仅写在移动 media；改后须桌面抽检短视频/精选/**乐团目录**。  
7. 凡移动-only 的 critical / CSS，**禁止**在无 `@media` 保护时污染桌面；反之，全端语义**禁止**被媒体查询误锁在移动。  
8. 改分类列表行数时，`post_title_row`=`post_title_row_mobile`，并写 `post_excerpt_row`；场景默认见 §7.7.6，**禁止日更覆盖已配置**。
