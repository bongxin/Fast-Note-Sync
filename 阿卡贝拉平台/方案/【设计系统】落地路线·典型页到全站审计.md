# 【设计系统】落地路线·典型页到全站审计

# BERNSINE 设计系统 · 落地路线图（审计 → 逐页调整）

> 版本：v1.2 · 2026-07-26  
> 配套规范：`design_system_spec.md` **v2.5**（含桌面策略 §2.1、§9 写作例外）  
> 原则：移动锚点打样 → 全站移动系统页 → **桌面响应调整（同源 Token，异构壳层）** → 工程收敛

---

## 1. 总流程

```
规范 v2.5（目标态，含桌面策略）
    → Phase A 移动锚点页打样（4 页优先，见下）
    → Phase B 移动系统页全量（P01–P25）
    → Phase D 桌面响应调整（跟进移动成果，按桌面习惯）
    → Phase C Token / critical 工程收敛（可与 A/B/D 穿插）
    → Done：两端元素级按规范实现
```

> **专业约定：** 桌面不是 Phase B 的「顺便放大」。共享 Token 可早改；壳层与面板单独 Phase D，避免把底栏/抽屉逻辑泄漏到桌面。

每页最小闭环：

1. **审计**：截图 + 对照清单（移动用 §2，桌面用 §2 + 桌面项）  
2. **调整**：先共用组件，再页级特判  
3. **验收**：清单全绿；例外写回规范 §9

## 5. Phase D · 桌面响应调整（专业重点）

### 5.1 策略摘要

- **对齐：** Token、选中语义、阅读层级、按钮/空态  
- **不搬：** 底栏、抽屉主路径、手机 gutter、触控-only 尺寸  
- **详规：** `design_system_spec.md` §2.1  

### 5.2 桌面锚点（先打样）

| 序 | 页面 | 焦点 | 状态 |
|----|------|------|------|
| D-A1 | 分类·乐团（桌面） | `#filter-top` 面板选中态 + 列表卡 | ✅ 随 A1 |
| D-A2 | 文章详情（桌面） | 阅读字号/行长/限宽 | ✅ 随 A2 |
| D-A3 | 首页（桌面） | 模块限宽、暖色、与移动模块语义一致 | ✅ 2026-07-26：模块内 1200 限宽；推荐/网格分类芯片改 facet（冷灰+浅底描边）；页托底 list-bg；卡信息区已对齐乐团 |
| D-A4 | 快讯（桌面） | 限宽横排芯片 + tipoff/排序条 + list-bg 白卡 | ✅ 随 A3 |

### 5.3 桌面全量扫描顺序

1. 全局：`:root` Token、桌面筛选选中、list-bg  
2. 模板 L 各分类归档桌面  
3. 模板 R 详情桌面  
4. 快捷入口桌面（快讯/专栏/文档/导航/公告）  
5. 功能页（我的/发布/认证）桌面  
6. 赛事/招募等大模块桌面  

### 5.4 风险清单（改桌面时自检）

| 风险 | 规避 |
|------|------|
| critical CSS 无 media 写出桌面 | 移动 critical 必须包在 max-width:768 |
| 桌面误藏筛选 | 如 links 桌面 `display:none` 的过滤器要有桌面替代面板 |
| 双套选中态 | 禁止保留「移动描边 + 桌面实心白字」长期并行 |
| 把双列封面比锁死 | 桌面网格按容器宽度重算 |

## 7. 执行约定

1. 移动 Phase A/B 与桌面 Phase D **共享 Token 改动**，壳层改动分开审。  
2. 改桌面前先确认：该样式是否被 `max-width:768` 保护；没有则先加保护再改移动。  
3. 发现「桌面必须与移动不同」→ 写入规范 §2.1 / §9，不写魔法数。  
4. 认知序（标签排序）两端同一数据源，桌面只改呈现。
