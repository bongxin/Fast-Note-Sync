# 全站排序对照清单

## 开发要点

### 总原则（产品）
1. **内容流**（推荐 / 视频 / 短视频分类 / 精选 / 教程 / 赛事）：偏**新鲜度**（`post_date` / `new`）
2. **目录库**（乐谱 / 乐团 / 音乐人 / 组织）：偏**热度**（`views`）
3. **探索**（随机 / Shorts 池洗牌 / 推荐里的 explore）：可选手动或混排一角，**不当唯一默认**
4. **个性化**仅落在首页「推荐」混排与搜索「为你推荐」，勿与 Tab「精选」抢语义

### 首页推荐混排（细节）
```
有兴趣画像：匹配 ~40% + 近稿 ~30% + 探索补齐
无画像访客：近稿 ~40% + 热门(views) ~30% + 探索补齐
各组内部用访客/用户 seed 洗牌，再拼成 post__in
```
- 缓存：transient，按用户或 Cookie `b2child_rec_vid`
- 父主题模块本身按日期；子主题注入 `post__in` 后改为编排序

### 父主题分类排序枚举
| `post_order` | 含义 | WP 行为 |
|--------------|------|---------|
| `new`（或空） | 最新 | 默认 `post_date`（`new` 在 switch 中无专门 case） |
| `random` | 随机 | `orderby=rand` |
| `views` | 最多浏览 | `meta_key=views` |
| `like` | 最多喜欢 | `b2_vote_up_count` |
| `comments` | 最多评论 | `comment_count` |

### 不一致 / 注意点
1. **短视频分类「最新」vs Shorts 沉浸「洗牌」**：故意双轨——列表发现新片，沉浸模拟刷流。
2. **推荐混排 ≠ 分类「随机」**：推荐是「近稿+热门+画像+探索」加权；分类随机是纯 rand。
3. **空 `post_order` 时按钮文案**可能显示「排序」而非「最新」——故内容流显式注入 `new`。
4. **`views` 排序缺 meta 会整帖消失**——已保底；新频道上线仍须确认。
5. **首页推荐无「排序」下拉**：改观感只能调混排比例或日更抬新，不能点「最多浏览」。
6. **精选(quality) 默认最新**：与「运营精选池」名字略冲——当前按内容流处理；若以后要「编辑置顶序」需另做 sticky/menu_order，勿与随机混用。
7. **乐团 views 校准（2026-07-26）**：按 B 站粉丝为主回写浏览量，使目录「最多浏览」贴近站外热度；**周更 cron** `band_hotness`；见 `band_views_calibration_dev_memory.md`。
8. **其它分类真假感（2026-07-26）**：乐谱/音乐人/组织/赛事/视频短视频精选/教程已校准；**周更** `views_realism`。
9. **全站认知包（2026-07-26）**：筛选标签 + 快捷入口 taxonomy + 标签云/搜索建议 + 练习 menu_order；总账 `platform_cognition_map_dev_memory.md`；周更 `filter_tags` + `cognition_pack`。
