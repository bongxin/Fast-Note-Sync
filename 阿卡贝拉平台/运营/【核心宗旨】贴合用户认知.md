# 【核心宗旨】贴合用户认知

## 运营宗旨（重点 · 必须遵守）

**贴合用户认知**是本站重要运营宗旨之一：站上「看见什么、先看见什么、怎么排」要符合用户在真实世界里对阿卡贝拉圈的心智预期，而不是后台录入顺序、创建先后或算法巧合。

### 一句话
用户打开筛选、目录、搜索建议、标签云时，顺序应像「懂行的人在脑子里排」——热门团靠前、新年份在前、城市按行政区划认知序、语义档位（难度/语种等）按常用习惯，而不是数据库 id 或录入先后。

### 两大目标（2026-07-26 明确 · 必须同时满足）

1. **现状对齐**：现在所有页面上的所有筛选标签 / 子分类，都要按客户认知顺序排好。
2. **增量自动**：后续新标签、新子分类（例：新建「深圳」城市分类、新建「2027」年份标签）必须由定时任务**自动并入**并排到正确位置，禁止依赖人工每次拖拽。

例：
- 新增「深圳」乐团子分类 → 按行政区划插到广州后、杭州前（未入表新城插在港澳台前）
- 新增「2027」年份标签 → 排在「2026」前面（四年份新→旧）

### 决策优先级（冲突时）
1. **贴合用户认知**（本宗旨）
2. 真假感 / 拟真边界（不批量抬赞评、不造一眼假数据）——见 `ops_behavior_policy` / `engagement_realism_audit`
3. 渠道与运维中枢约定——见 `ops_channel_strategy` / `ops_roadmap_full`
4. 工程便利（录入先后、固定 id 序）——**不得压过 1**

### 覆盖面（凡属「发现序」都要过认知关）
| 面 | 认知要求（例） |
|----|----------------|
| 乐团目录 views | 贴近站外真实热度（如 B 站粉丝），MayTree 等头部认知不被乱序淹没 |
| 其它分类 views | 量级像真人浏览，跨分类不必对齐，忌一眼假 |
| 筛选标签 / 子分类 | 全站各分类 `b2_filter`：重排 + 从站内实际标签/子分类自动并入 |
| 快捷入口 taxonomy | 合集/快讯/文档/导航分类序可读 |
| 搜索建议 / 标签云 | 热实体前列，滤噪声 |
| 练习频道 | menu_order 可跟关联乐谱热度建议 |
| 文章评论（boost） | 话术按分类认知：乐谱谈排练读谱，视频谈听感，忌跨类套话 |
| 人工/探针评论修补 | **勿堆同一篇文章**；分散到不同内容；短口语、像真实网民；宁少勿齐、宁散勿齐 |

### 评论拟真硬性（2026-07-29 补）
- 探针/测试评论改写后：**必须迁到多篇不同帖**，禁止 5 条全挂在同一 `post_id`。
- 文案贴分类心智（视频听感、乐谱排练、教程跟练…），忌五条同主题散文。
- 与 `engagement_realism_audit`「赞/评宁少勿齐」一致；见 `probe_comments_cleanup_dev_memory.md`。

### 落地机制（勿当一次性脚本）
- **日更** `filter_tags`（05:45 上海）：全站筛选 **重排 + 自动并入**（年份/地区/语义维/实体维/子分类）
- **周更** `band_hotness` / `views_realism` / `cognition_pack`：热度与发现面词池
- 总账与探针：`platform_cognition_map_dev_memory.md`、`_probe_platform_cognition.py`
- 实现：`_ops_pack/jobs/filter_tags_cognition_weekly.php`

### 明确不做（避免误伤宗旨）
- 不批量抬赞/评冒充热度
- 不改 Shorts 洗牌等已约定的产品故意行为（快捷/主导航 IA 序见 `ia_nav_sort_dev_memory`，已定稿可改）
- 不把 B 站百万播放原样抄成站内 views
- 不自动「创建」不存在的 WP 标签 term（只并入已存在或已挂到文章上的标签；缺 term 的芯片 B2 会静默不显示）

### 后续开发约定
- 新分类、新标签、新发现面：**默认假设需要认知序**；能定时任务自动归位的，不要靠人工每次拖拽。
- 改排序/默认 Tab/筛选配置前：先问「外行会不会觉得怪？圈内人会不会觉得假？」
- 相关记忆交叉：`platform_cognition_map` · `taxonomy_filters` · `engagement_realism_audit` · `sorting_inventory` · `ops_scheduler`
