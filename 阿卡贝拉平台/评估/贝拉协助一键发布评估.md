# 贝拉协助一键发布评估

## 开发要点
- **需求（2026-07-24 · 项18）**：保留该能力方向；**须严格评估**。目标：贝拉对**已认证或特定身份**用户，协助**一键发布平台信息**（非后台管理）。
- **现状**
  - 贝拉 = 只读问答 + RAG + Safety（明确禁止后台）；**无写库、无调发布 API**
  - 发布入口独立：`#post-po-box` / 搜索行 `+` / 声场 FAB；权限由 B2 投稿与角色控制
  - 认证：`/verify` + `user_title`；另有 VIP / 种子 / 运营角色，**互不等价**
- **严格评估结论**

| 维度 | 结论 |
|---|---|
| 价值 | 高：降低认证创作者发快讯/声场/活动预告成本，贴合「节目/活动信息」运营 |
| 技术可行性 | 中高：REST 代填草稿 + 打开发布表单可行；**静默直接 publish 风险高** |
| 安全 | **高风险**：幻觉乱发、冒用身份、刷屏、绕过审核；与 Safety「只帮用户侧」边界需重划「代写可、代发须确认」 |
| 合规 | 须登录 + 身份门控 + 发布前用户确认；默认进「待审」优于直接公开 |
| 建议 | **保留方向，不做静默一键上线**；先做「门控对话 → 生成草稿 → 用户确认 → 调起发布表单/创建待审稿」 |

- **推荐门控（谁能用）**
  1. 已通过站内认证（有 `user_title` / verify 成功），或
  2. 白名单角色（editor / 指定 `meta` 如 `_b2_ops_creator=1`），或
  3. VIP 某一档（可选，勿默认全 VIP）
  - **排除**：未登录、未认证普通用户、种子拟真号（除非运营白名单）
- **推荐能力分层**
  - **P0（可做）**：贝拉内「帮我写一条活动快讯/声场预告」→ 出标题+正文预览 → 按钮「去发布」打开现有 `postPoBox` 并预填（仍由用户点提交）
  - **P1**：预填后创建 `draft` / `pending`；通知运营审核
  - **P2（慎做）**：真·一键 `publish`；仅白名单 + 频率限制 + 审计日志 + 可一键撤回
- **禁止**
  - 贝拉代发 wp-admin / 改设置 / 发他人名义内容
  - 未确认直接公开；用幻觉编造演出档期/联系方式
- **验收标准（若开工）**：非认证用户不可见入口；认证用户预填准确率人工抽检；误发可删；日志含 user_id / 草稿 id / 时间
- **未确认前不写发布写接口代码**
